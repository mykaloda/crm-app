# Moment — биржа моментов

Сайт по ТЗ «Биржа моментов»: продажа природных событий (дождь, первый снег, гроза, рассвет, метеоритный дождь) в конкретном городе как именного подарка. Полный цикл «покупка → ожидание → событие → архив» идет автоматически, без оператора.

## Запуск

```bash
npm install
cp .env.example .env.local        # по желанию
WEATHER_PROVIDER=simulated npm run dev
```

Открыть http://localhost:3000, админка — `/admin` (в dev пароль `admin`, в production задайте `ADMIN_PASSWORD`).

Нужен Node.js ≥ 22.13 (встроенный SQLite). Каталог из ТЗ (8 городов, 6 типов событий, цены) создается автоматически при первом запуске в `data/moment.db`.

### Режимы без ключей

Сайт полностью работает без внешних сервисов, чтобы его можно было посмотреть сразу:

| Сервис | Без ключей | С ключами |
|---|---|---|
| Оплата | Тестовая страница оплаты (деньги не списываются) | Stripe Checkout: карта, Apple Pay, Google Pay; Stripe Tax (`STRIPE_TAX=1`) |
| Погода | `WEATHER_PROVIDER=simulated` — детерминированный симулятор + ручной «сделать дождь» в админке | OpenWeatherMap One Call (основной) + Open-Meteo (подтверждение). Без ключа OWM — Open-Meteo, подтверждение моделью ECMWF |
| Email | Письма пишутся в журнал (админка → Outbox), код входа показывается на экране | Resend, PDF-сертификат во вложении |
| SMS | Журнал | Twilio |

### Проверить полный цикл за минуту

1. Купите «Следующий дождь в Париже» → тестовая оплата → страница «Спасибо» с сертификатом и ссылкой получателя.
2. Откройте ссылку получателя — состояние «ожидание» с погодой и прогнозом на 7 дней.
3. Админка → Events & monitoring → симулятор: Paris, 1.2 мм/ч → «Poll all cities now» два раза (начало фиксируется по двум опросам подряд).
4. Страница получателя стала live: таймер, температура, интенсивность.
5. Админка → Moments → «End now» (или 30 минут без осадков) → архив, картинка 1080×1350, журнал замеров. В каталоге открылся «Следующий дождь в Париже №2».

## Что реализовано (по разделам ТЗ)

- **Каталог (3):** один момент — один владелец; блокировка на 15 минут при оформлении; автогенерация следующего момента после события (бесконечная серия / раз в сезон / окно на Новый год); аукционы (старт, шаг, дедлайн, автопродление на 5 минут); разовые моменты из админки.
- **Сценарии (4):** гостевая покупка, имя получателя/дарителя, поздравление до 200 символов, контакт (email/телефон), отправка сразу или по дате; PDF-сертификат; страница `/m/{token}` в трех состояниях; изменение контакта в кабинете до события.
- **Страницы (5):** `/`, `/moments`, `/city/{slug}`, `/moments/{slug}`, `/checkout`, `/order/{id}`, `/m/{token}`, `/auction/{id}`, `/account`, `/how-it-works`, `/faq`, `/terms`, `/privacy`. Mobile-first, EN/RU, доллары с ориентировочной конвертацией (EUR/GBP/UAH/RUB).
- **Мониторинг (6):** опрос каждые 5 минут по городам с отслеживаемыми моментами; начало — условие в двух опросах подряд; окончание — 30 минут без условия; значения у порога проверяются вторым источником, расхождения уходят на ручное решение в админку; рассвет и метеоры — по астрономическому расчету/календарю; все замеры и сырые ответы хранятся; повтор при сбое API и алерт админу после 3 неудачных опросов подряд.
- **Уведомления:** подарок отправлен, событие началось, закончилось (ссылка на архив), перебита ставка, победа, напоминание об оплате. Получатель выбирает канал при первом открытии, может отписаться и удалить запись.
- **Админка (8):** дашборд (продажи день/неделя/месяц, конверсия оформления, доля моментов в ожидании, средний срок до события по городам), города и цены, типы событий (пороги, сезоны, окна, тексты), моменты (ручной старт/стоп, снятие с продажи, разовые моменты, окна метеоритных дождей), заказы (поиск, повторная отправка, смена контакта, возврат минус комиссия), журнал замеров и спорные фиксации, аукционы, FAQ и отзывы, журнал всех сообщений.
- **Нефункциональное (9):** SSR каталога и городов, OG-картинки, sitemap/robots, токены получателя 43 символа (32 случайных байта), honeypot и минимальное время заполнения форм, платежные данные только у Stripe, анимации уважают `prefers-reduced-motion`.
- **Юридическое (10):** черновик оферты (цифровой подарок, а не право на явление; правила фиксации; без срока; возврат; спорные фиксации и 14 дней на претензию; согласие дарителя; правила аукциона; налоги) — **требует проверки юристом**.

## Мониторинг в production

- Долгоживущий сервер (Railway, Docker, VPS): встроенный планировщик в `instrumentation.ts` запускает монитор раз в минуту (каждый город опрашивается не чаще раза в 5 минут).
- Serverless: `INTERNAL_SCHEDULER=0` и внешний cron каждые 5 минут на `GET /api/cron/tick` с заголовком `Authorization: Bearer $CRON_SECRET`.

Stripe webhook: `POST /api/stripe/webhook`, события `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.expired`.

## Отличия от рекомендованного стека

- **SQLite вместо PostgreSQL** — чтобы проект запускался без внешних сервисов. Вся работа с БД сосредоточена в `lib/*.ts`, схема в `lib/db.ts` переносится в PostgreSQL почти без изменений. Для Vercel/serverless перенос на Postgres обязателен (файл SQLite там не сохраняется); на Railway/Docker достаточно постоянного тома (`DATABASE_PATH`).
- **Планировщик вместо Redis + BullMQ** — для MVP хватает периодического тика с защитой от параллельного запуска и повторами запросов. Очередь стоит добавить при росте числа городов.
- **Web push** — канал заложен, но в MVP сообщения только журналируются (в ТЗ он опционален).
- Письма аукциона пока только на английском.

```
lib/monitor.ts  движок фиксации событий    lib/weather.ts  погодные провайдеры и симулятор

lib/i18n.ts     тексты EN/RU               lib/time.ts     часовые пояса, восход солнца
```
